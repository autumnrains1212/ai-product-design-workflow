# 可编辑设计与交互落地

根据需求基线制作适合目标平台的体验。用户只要求需求文档或无界面能力时，交付对应规格与验证材料，不附加无关界面；需要设计时沿用用户指定的工具、参考和设计系统。

网页 UI 设计、实现或视觉验收时，先读取[风格选择](web-style-selection.md)和[共享网页基础](web-ui-foundations.md)，再按实际任务读取一个主风格。用户明确要求的品牌、风格、平台或组件库优先，已有项目优先沿用其有效设计系统；未指定时可根据场景选择并说明依据。发现冲突时记录取舍，不自动改造既有页面或安装组件库。纯需求文档、无界面任务和原生移动端不因本规则加载网页规范。

## 从规格确定设计范围

先识别用户要完成的任务、业务对象、入口、主路径和适用状态，再决定表单、对话、列表、画布、批量操作或其他交互形式。AI 能力不决定所有产品都必须采用聊天界面。

将需求中的功能与验收规则映射到页面、组件或交互节点。针对实际功能检查：

| 能力 | 需要表达的关键内容 |
|---|---|
| 普通功能 | 输入与校验、结果、错误、必要的权限或空状态 |
| 问答与检索 | 问题、可用资料范围、来源与适用性、信息不足、纠错与继续询问 |
| 内容生成或提取 | 输入约束、处理中反馈、可审阅结果、部分或无效输出、必要的编辑与采用 |
| 工具执行 | 建议与执行的区别、授权对象和参数、执行进度、回执、部分成功与可行的补救 |
| 异步或可恢复操作 | 已知业务状态、状态未知、离开后的恢复入口、重试及原对象身份 |
| 持久化编辑 | 草稿与保存状态、失败重试、未保存离开；有并发风险时增加版本冲突处理 |

这些是按能力选择的设计检查项，不要求每个产品制作全部状态。

## 制作可编辑内容

先检查文件访问、可用字体、组件、变量、样式及目标工具能力。复用适用资产；整体风格参考与具体页面内容分别确认。跨工具重建时说明组件关系是否保留，不声称已同步到不可访问的源文件。

按平台与内容设置布局、尺寸、间距、断点和安全区域。需要原生可编辑设计时，使用真实文本、矢量、组件与适用的布局能力；整页截图只能作为参考。代码原型可编辑不等于已交付指定设计工具中的原生图层。

结果表达应让用户知道系统依据、当前状态、下一步选择和动作后果。不要把不确定状态写成确定结论，也不要把未经核实的内容默认采纳。设置合理的信息层级、键盘与焦点行为、对比度、文本溢出和操作反馈。

## 原型、模拟与真实接口

按交付范围接通可运行的核心路径和适用恢复分支。没有可用接口时，可用独立于终端用户界面的评审开关模拟响应，并明确标记模拟输入、延时和返回值。定时跳页或固定样例不能证明真实模型、工具或数据操作已工作。

只读重试保持原操作语义。异步操作离开后，按需求提供可发现的恢复入口并保留必要身份；不能用旧状态冒充最新状态。编辑、保存、采用、撤销和取消仅在实际支持时设计为可用动作。

## 保存与运行核验

写入设计或配置后读取现场确认实际结果，再在预览或运行环境触发。普通连接线、按钮外观、脚本无报错或目标图层存在，都不能单独证明交互已保存并可操作。

工具失败后先核实现场，再按实际支持能力修复或采用替代方式；不无限重复同一无效操作。保留已完成内容，并准确说明尚未配置、尚未运行或缺少访问的部分。

## 分层记录验收

- 结构：文案、层级、组件与布局是否可编辑，是否符合目标平台和范围。
- 视觉与可访问性：裁切、重叠、层级、响应式、焦点、键盘和状态反馈。
- 网页规范：按共享基础与本轮选定的主风格检查适用的语义色、文字与按钮对比度、字号间距、组件状态、响应式和键盘操作；记录风格选择、必要派生、实际检查与未覆盖项。
- 配置：触发条件、目标、数据关联及适用的失败、返回与恢复入口。
- 原型运行：实际触发主路径与相关分支，检查目的状态和操作对象。
- 产品运行：模型、接口、权限、持久化、并发及业务回执需要在实际实现中另外验证。

每层记录实际证据与未覆盖事项，不以其中一层代替其他层。完成当前授权范围后交接设计位置、查看方式、关键交互规则及待实现部分。
