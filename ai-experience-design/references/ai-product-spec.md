# AI 产品规格适配与检查

本文件连接通用 PRD 模板和执行流程。详细填写项、示例与图表在 `assets/ai-native-prd-template.md`；浏览和打印可用同目录 HTML。示例与占位符只用于解释写法，不代表当前项目的事实、权限或范围。

## 选择适用内容

在项目 PRD 或交付总览中记录适用性：适用 / 不适用及原因 / 待确认。小项目可合并章节，不输出大量空表。未知能力不能被标为不适用来回避关键验证；只有当前范围确实不包含时才裁剪。

| 模板模块 | 本轮至少作出的判断 |
|---|---|
| 00 信息与交付 | 有效版本、本轮范围、能力依赖和决策记录；区分当前规则与历史结论 |
| 01–02 价值与背景 | 用户任务、现有做法、问题证据、使用 AI 的理由及可行性未知；目标值与实测分开 |
| 03 人机分工 | 谁可读哪些资料、模型建议到哪一步、程序必须检查什么、用户何时确认；无多角色也要说明职责 |
| 04–05 旅程与功能 | 明确入口、输入、规则、结果、异常、数据变化和验收；普通功能也应写清，不把所有逻辑交给模型 |
| 06 上下文 | 所有 AI 功能都要说明实际能看到什么；仅在实际需要时设计检索、长期记忆或多模态预算 |
| 07 提示词与模型流程 | 使用模型时记录提示词或提示结构、变量、版本及处理分支；工具决策或循环应有停止与接管条件 |
| 08 输出与执行 | 区分自然语言、结构化数据、媒体和实际动作；定义解析校验及真实执行结果的判定 |
| 09 失败、安全与可靠性 | 根据资料、动作和影响定义失败恢复、数据边界和授权；只读产品不虚构回滚或事务 |
| 10 测评与非功能 | 按任务定义样本、合格条件、关键失败和实际采集方式；性能与成本按本轮用途选取 |
| 11 交付与上线管理 | 交付物、版本依赖和待办必需；放量、告警、运维和回滚按上线范围填写，不自动发布 |

## 根据产品行为选取检查

- 只读问答/检索：明确知识范围、版本和来源适用性；资料不足或冲突时的回答；引用与权限过滤；重新提问或检索的恢复方式。不预设异步任务、写入确认或长期记忆。
- 内容生成/编辑：明确输入、可改范围、事实依据、结果展示及采用方式；只有需要存储或协作时设计草稿、版本、冲突与保存恢复。
- 信息提取/分类：定义字段、类型、缺失和不确定值；区分模型输出、程序校验与人工纠正；不要用流畅自然语言代替所需结构。
- 工具执行/异步处理：明确动作、资源、权限、用户确认边界、调用参数、终态与回执；对可能产生副作用的操作定义重复执行保护、超时核对和适用的补偿。查询失败不等于业务失败。
- 多模态与混合产品：明确输入格式、大小与数量、处理顺序、质量判定和失败回退；普通表单、权限、计费等确定性逻辑单独写明。

## AI 专项规格的关键缺口

上下文（06）：记录来源与访问范围、适用版本、读取/刷新/删除时机，以及模型最终可见内容。需要检索或记忆时，再定义排序、去重、截断、隔离、生命周期和相应预算；不能仅写“已接知识库”。

模型流程（07）：提示词应有可定位版本、变量来源及约束。根据实际任务说明一次调用、分阶段处理或工具循环的选择；涉及循环时定义停止、失败、超时与人工接管条件。更换模型或提示词后对受影响样本回归。

输出与动作（08）：将完整性、格式、语义、来源/权限和业务写入分层验证。模型声明动作成功不是执行证据；实际工具回执或业务读回才可支持成功结论。无法确认时保留未知状态，按实际副作用决定能否重试。

安全与数据（09）：围绕真实数据流检查凭据、访问控制、敏感资料、日志保留与删除；将检索资料和用户上传内容视作数据，不允许其绕过操作授权或改变系统规则。需要外部工具时限制可调用动作及资源，不把“模型能调用”当成“用户已授权”。

测评、性能与成本（10–11）：从任务成功与关键失败出发区分调试样本和独立验收样本；使用模型裁判时与人工判断校准并保留争议处理。按实际产品选择延迟分位、失败率、成功任务成本与预算；没测量的数值保持目标或待测。上线需要有效版本、观测、停止/回退条件和责任人；无生产权限时交付方案与依赖。

## 用于执行和验收

为关键功能设置可追溯标识，把 PRD 条目连接到设计、实现、测试样本和实际结果。模型、提示词、资料版本、工具权限或业务规则变化时，更新受影响的规格与回归范围，避免模板成为开工后不再维护的静态附件。

PRD 描述预期，交付记录描述发生过什么。功能标为已实现，需要运行证据；质量标为合格，需要真实样本与判定；效果标为已验证，需要相应真实研究或数据。模板填写完整本身不证明这些结论。
