# 共享网页 UI 基础

本文件适用于六种网页风格以及项目已有设计系统，只规定跨风格的可用性、状态与验收。具体色板、字体、间距和版式由[风格选择](web-style-selection.md)决定，不从未选中的风格引入默认值。

## 制作前

先读取产品任务、平台、已有页面、品牌、组件、令牌、断点与实际字体资源。优先复用项目当前可用资产；规范文件不是现成组件库，字体名称也不代表字体已安装。前端框架、设计工具和外部字体服务按用户选择及现有环境决定。

新风格必须具体落实到表面、正文、次级文字、边框、交互、焦点和状态等语义令牌；基础色不能无差别用作文字、边框和按钮。源中未定义的颜色、阴影、断点或尺寸，可按项目补充并记录，不伪装为来源原值。

字体缺少中文或所需字重时，使用可用的项目或系统回退并检查混排、字号和换行。只加载实际需要的字重；表格、数字和代码的对齐按内容验证，不因来源给出一个字体名就假设它是等宽字体。

## 结构、组件与响应式

- 依据任务安排标题、说明、主要动作、内容和反馈；按钮与链接使用对应语义，标签说明动作及对象。
- 按适用性设计默认、hover、focus-visible、active、disabled、loading、error 和成功状态。无对应功能的状态不用创建；加载反馈不代替真实业务状态。
- 表单提供关联标签、说明及可定位的错误，保留失败时的有效输入；占位符不能作为唯一标签。
- 弹窗或抽屉按用途管理焦点、关闭和返回位置；避免长内容遮挡关键操作。
- 列表与表格保留列名、单位、选择范围和排序/筛选状态。按实际目标视口检查空、加载、无匹配、错误、长文案及溢出；窄屏中的重排或横向滚动须保留任务和操作。
- 无实际用途的装饰动效、降低可读性的透明叠层和混杂视觉隐喻不应成为风格的必要条件。需要动效时考虑减少动态效果的偏好。

## 可执行的可访问性目标

以 WCAG 2.2 AA 为目标，具体定义与例外以 [W3C 对比度条款](https://www.w3.org/TR/WCAG22/#contrast-minimum)和[目标尺寸条款](https://www.w3.org/TR/WCAG22/#target-size-minimum)为准：普通文字对比至少 4.5:1，大号文字至少 3:1；指针目标至少 24×24 CSS 像素或满足对应例外。部分来源建议 44px 以上的触摸目标，可作为场景中的可用性建议，不把它误写成全部 AA 条款的统一阈值。

对每种实际前景/背景、主题与交互状态测量。来源基础色不保证任何组合都合格：浅粉/浅绿通常需要深色文字，亮蓝或橙色搭白字也可能不足；深色主题中的深蓝文字同样可能不清楚。必要时采用有记录的语义派生，不能靠降低标准来保持色值。

使用键盘检查顺序、可见焦点、触发、退出和焦点返回；检查可访问名称、字段错误和必要的状态通知。关键信息不只靠颜色、动画或仅悬停提示表达。按任务检查缩放、窄屏、触摸及适用辅助技术，并记录实际检查范围。

## 交付与迁移

界面、原型配置、真实运行、模型质量和真人效果分别记录。没有执行的对比检查、键盘/读屏检查或真人研究保持待验证，不能因选了风格或自动扫描通过而宣称整体合规。

已有产品按本轮影响范围映射令牌与组件，不自动批量换肤。局部修改检查受影响内容和相关共享资源；只有用户要求全面迁移时才按该范围推进。交付时写明所选风格、采用值与偏离原因、实际检查、问题修复及未覆盖项。
