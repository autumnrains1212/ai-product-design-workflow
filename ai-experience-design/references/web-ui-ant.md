# 网页端 UI 设计规范：Ant 参考体系

## 适用范围与来源

本规范用于需要设计或实现 Web 界面的产品。它依据本包附带的 `ant` 技能与设计说明原文快照整理，侧重结构清晰、信息密度适当和企业级任务效率。源技能标注作者 `typeui.sh`、许可证 `MIT`；包内保留了[技能原文快照](../assets/ant-source-skill.md)和[设计说明原文快照](../assets/ant-source-design.md)，便于核对与迁移。下列具体数值来自随包来源快照，不能一概声称是 Ant Design 官方默认值，也不代表已经安装 Ant Design 组件库。

本文件在[风格选择](web-style-selection.md)确定采用 Ant 企业后台风格时读取，并遵循[共享网页基础](web-ui-foundations.md)。只做需求文档或无 Web 界面时不增加界面设计工作。开始设计前检查项目目标、既有页面、品牌、设计令牌、组件库、断点、可用字体及指定技术。优先复用当前项目中适用的资产；用户明确指定的品牌、风格和技术优先。数据密集的管理类网页没有其他体系时，可采用本规范作为起点；其他网页按任务选择对应风格。移动原生界面不套用这份 Web 规范。

规范冲突时先记录冲突与影响：保留已有系统的语义和真实约束；若某种颜色、尺寸或交互无法满足无障碍要求，调整对应语义令牌或组件实现并说明原因，而不声称仅因为采用某个体系就已满足标准。

## 基础令牌

随包来源快照中的规范数值如下；以下颜色是基础色板，实际文本、边框、背景和状态用途应以语义令牌映射，并在实际组合上验证：

| 令牌角色 | 值 | 使用与约束 |
|---|---|---|
| 主色 `primary` | `#1677FF` | 主要交互色；不直接假设白字按钮或白底文字通过对比度 |
| 次色 `secondary` | `#8B5CF6` | 按信息层级少量使用；不以颜色替代文本或图标含义 |
| 成功 `success` | `#16A34A` | 成功状态色；文本需另选达标的语义前景色 |
| 警告 `warning` | `#D97706` | 警告状态色；应同时提供可理解的状态说明 |
| 危险 `danger` | `#DC2626` | 错误或危险状态色；避免仅凭红色区分后果 |
| 背景 `surface` | `#FFFFFF` | 默认浅色表面 |
| 正文 `text` | `#111827` | 默认正文色，具体前景与背景组合须测量 |

`DESIGN.md` 中 `neutral: #FFFFFF` 是由表面色派生的兼容字段，不足以构成完整中性色阶。按项目实际补充边框、次级文字、禁用等所需令牌并记录值与来源；不得把缺失的值描述为源规范已提供。若需要深色主题，另定义并检验深色语义令牌，不将浅色令牌直接反转。

- 字体：主要文本及展示使用 `Plus Jakarta Sans`，等宽文本使用 `JetBrains Mono`。字体不可用或中文字形缺失时使用项目现有或系统可用的无衬线/等宽回退，检查混排与授权；不得假设已安装字体或自动引入外部字体服务。
- 字号：`12 / 14 / 16 / 20 / 24 / 32px`。源 `DESIGN.md` 给出一级标题 `2rem`、正文 `1rem`、等宽大写标签 `0.75rem`；在根字号为 16px 时分别为 32、16、12px。根字号或用户缩放不同需按实际渲染核对，不以缩小正文来挤出空间。
- 字重：可用范围为 `100 / 200 / 300 / 400 / 500 / 600 / 700 / 800 / 900`；实际仅选择已加载且有需要的字重，保持相同层级一致。
- 间距：`4 / 8 / 12 / 16 / 24 / 32px`。将其映射为项目令牌，用相同规则处理组件内边距、元素间距和区块间距；较大页面间距可按项目需要推导并记录。
- 圆角：随包 `DESIGN.md` 来源快照定义 `sm: 4px`、`md: 8px`。将组件圆角映射为语义令牌；既有项目有明确规范时沿用既有映射。

令牌示例（用于新项目起步，具体名称按现有代码体系调整）：

```css
:root {
  --color-primary: #1677ff;
  --color-secondary: #8b5cf6;
  --color-success: #16a34a;
  --color-warning: #d97706;
  --color-danger: #dc2626;
  --color-surface: #ffffff;
  --color-text: #111827;
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-6: 24px;
  --space-8: 32px;
  --radius-sm: 4px;
  --radius-md: 8px;
}
```

颜色的具体语义派生及可用组合需要项目定义；上面这段不能作为已完成无障碍验证的证据。

## 布局、组件与交互

先用一句话写清页面的用户任务，再组织标题、说明、主要操作、数据和状态。用间距、字号、字重与分组表达层级；在内容量大时优先保障扫描、筛选和定位。根据任务选择导航、表格、表单或卡片，不强制所有页面采用同一种版式。组件先复用项目已有实现，不凭规范名称自动安装新依赖。

| 组件或场景 | 组成、变体与行为 | 适用状态及窄屏检查 |
|---|---|---|
| 按钮与链接 | 按操作语义使用原生按钮或链接，区分主要、次要及危险操作；同一层级保持令牌与间距一致。若项目无既有尺寸，8/16px 内边距与 4/8px 圆角可作为待验证起点，非源规范强制尺寸 | 按适用性检查默认、悬停、键盘可见焦点、按下、禁用、加载和失败；长文案可换行或重排，防止遮挡。提交中的防重复需与真实业务语义一致 |
| 表单 | 每项有可关联的标签；必填、说明和错误与具体字段对应；输入、选择和提交使用明确名称。示例占位符不能代替标签 | 检查默认、聚焦、已填写、禁用、校验错误、提交中及成功/失败；长标签与错误文案在小屏下完整可见 |
| 对话框或抽屉 | 清楚表达任务、影响与确认/取消；对破坏性或产生外部副作用的动作体现具体对象及用户确认边界 | 打开后焦点可达，键盘可操作关闭；关闭后焦点回到合理位置。内容较长时允许内部滚动，不截断操作 |
| 表格与列表 | 保留标题、字段标签、单位及排序/筛选状态；信息密度服务于可读性。批量操作显示选择范围和可用动作 | 检查空、加载、错误、无匹配及长文本；小屏可按需求使用可辨识的横向滚动或重排，操作不能消失或依赖仅悬停 |
| 系统反馈 | 对空、加载、错误、成功及部分结果分别说明已知状态、受影响对象与可用下一步 | 不把查询失败表述成业务失败；不能只用颜色或转圈传达信息。数据与用户输入的保留行为以实际实现为准 |

上表是按当前产品能力选用的规则；不适用的组件和状态无需创建。响应式应检查用户指定的目标设备、实际内容与放大缩放情况；源码没有规定通用断点，不要将任意固定值写成源规范要求。

## 无障碍与可执行检查

以 WCAG 2.2 AA 作为目标，结合真实设备、键盘、辅助技术和适用内容逐项验收。普通文本的最低对比度目标为 4.5:1，大号文本为 3:1；定义和例外以 [WCAG 2.2 Contrast (Minimum)](https://www.w3.org/TR/WCAG22/#contrast-minimum) 为准。对每种实际的文字、背景、交互状态和关键非文字边界分别检查；不以单个分值宣称整体 AA 合规。

基础色必须保留以便追溯，但应使用通过检查的语义前景/背景组合。按白色 `#FFFFFF` 比较：`#1677FF` 约 4.10:1、`#8B5CF6` 约 4.23:1、`#16A34A` 约 3.30:1、`#D97706` 约 3.19:1。这些颜色直接用作白底普通文字或白字同色背景均低于 4.5:1；需选择合适的前景、背景或经记录的派生令牌，并测量最终组合。不要仅凭颜色数值或自动工具评分宣布合格。

- 使用键盘逐项检查 Tab 顺序、可见焦点、触发和退出；组件不能仅靠鼠标悬停操作。
- 用可访问的名称、标签及语义表达控件；检查错误能被定位和理解，状态不只靠颜色、图标或动画。
- 检查指针目标至少为 24×24 CSS 像素，或符合 [WCAG 2.2 目标尺寸例外](https://www.w3.org/TR/WCAG22/#target-size-minimum)（例如符合条件的目标间距）；同时检查长内容、缩放、屏幕变窄和触摸操作时仍可使用。
- 考虑减少动态效果的偏好；只在有实际意义时使用动画，不能让关键反馈只存在于动画中。
- 对不可执行的检查记录依赖与未覆盖范围；人工审查、自动扫描和真实用户验证各有边界。

## 文案与反例

文案保持简洁、清楚、友好、专业，优先用动作和对象说明后果。示例：用“保存修改”代替含义不明的“确定”；用“未能保存，请重试”代替仅显示“错误”。若真实结果尚未知，说明“结果暂时无法确认”，不要直接写成成功或失败。

不要在相邻组件上随意使用不同间距；不要把占位符当作唯一标签；不要只靠红绿表示状态；不要因为视觉需要隐藏键盘焦点；不要加入无用途的装饰动画或混合互相冲突的视觉隐喻。每处例外应有项目原因和验证依据。

## 已有系统迁移与交付检查

现有产品先盘点页面、令牌、组件和实际状态，将本规范映射到现有系统，按影响范围逐步修正；不因接入规范批量替换用户品牌、整体视觉或功能。新模式与旧组件并存时说明适用范围及迁移路径；用户明确要求全面迁移时才按该范围执行。不同指定设计工具或前端栈按其自身组件与实现能力落地，不虚构已存在的资产。

交付前，记录以下检查的结果和证据：

1. 任务、适用范围、所选设计系统及用户指定的例外明确；关键界面使用一致的语义令牌。
2. 实际页面字号、层级、间距、圆角和对比度已按目标环境核对；未提供的中性色或深色令牌有明确来源。
3. 组件的适用状态、键盘焦点、输入方式、错误与恢复已实际触发；空、加载和长内容等分支按需覆盖。
4. 目标视口、窄屏、文字放大和实际内容下无影响任务的裁切、重叠或隐藏操作。
5. 图层可编辑性、原型配置、运行行为分别记录；仅有截图、设计配置或代码不等于真实功能已验证。
6. 记录自动与人工检查、发现的问题、已修复项和未覆盖范围；没有执行的无障碍或真人验证标为待验证。
