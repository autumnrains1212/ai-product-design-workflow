# 网页风格选择

网页 UI 需要设计、实现或视觉验收时，先读本文件与[共享网页基础](web-ui-foundations.md)，再读取本轮选定的风格。常规制作仅加载一个主风格；明确要求比较方案时按需读取相应候选。只写 PRD、无界面任务和原生移动端不因本规则选择网页风格。

## 优先级与选择顺序

1. 沿用用户本轮明确指定的品牌、风格、组件库和参考；同一项目已有有效设计系统时优先复用，除非用户明确要求迁移。沿用自有品牌时读取其项目规范与共享基础，不强制加载预设风格的色板和字体。
2. 有明确风格名时，按下面的名称或别名选取。两个要求冲突时说明影响并解决真正阻塞的分歧；不能静默把两个完整色板、字体和组件语法混合。
3. 无明确风格且无现有设计系统时，根据用户任务、内容密度、使用环境选择一个主风格，用一句话说明依据。任务不清楚时可先用 Clean 作为可调整的起点，不把这个选择说成用户已确认。
4. 正常制作只加载共享基础和一个主风格。用户明确要求对比时可按需读取候选，分别给出差异或在授权范围内制作独立方案；选定后沿用一套令牌与组件规则。不要默认制作六套界面或强迫用户先答风格问卷。

## 六种可选风格

| 标识与中文名 | 适合的任务与视觉特点 | 读取文件 |
|---|---|---|
| `ant` · 企业后台 | 数据密集的管理、工单、审批、表格与表单；清晰层级和一致操作 | [Ant 网页规范](web-ui-ant.md) |
| `clean` · 清爽工具（清爽简洁） | 轻量工具、设置、上传转换等；克制用色、留白与直接操作 | [Clean](web-styles/clean.md) |
| `editorial` · 编辑阅读（内容阅读） | 知识、报告、文章与长结果；阅读顺序、排版和内容层级 | [Editorial](web-styles/editorial.md) |
| `friendly` · 亲和消费（亲和友好） | 面向普通消费者、新手引导和轻量服务；柔和表面、易理解反馈 | [Friendly](web-styles/friendly.md) |
| `enterprise` · 深色工作台（深色控制台） | 已明确选择深色的监测、运维或云资源工作台；模块与数据层级 | [Enterprise](web-styles/enterprise.md) |
| `agentic` · AI任务助手（任务委托） | 用户确实委托多步任务、审阅结果和决定下一步；输入、过程反馈和成果聚焦 | [Agentic](web-styles/agentic.md) |

“企业级”本身不等于深色：数据管理默认可选 Ant；明确的深色环境/需求再考虑 Enterprise。“使用 AI”本身也不等于对话或多步委托：按实际任务选择，Agentic 不改变权限、确认或执行语义。

## 落实为项目决定

在项目已有 PRD、设计说明或交付记录中简记：主风格标识、选择依据、继承的品牌/组件、采用的语义令牌、必要的字体回退或可访问性调整。无需单独生成新的空文档。

各风格文件中的源值用于起步与追溯；项目具体值和派生值分别标记。风格改变的是呈现方式，不能擅自增加页面、聊天、任务队列、数据库或业务权限，也不能把隐藏内部推理作为过程反馈展示。

一套产品保持同一组基础令牌和组件规则。确需不同主题时，保留相同的语义与交互行为，分别验证各主题的可读性、状态和响应式；不要用拼接多份风格来代替主题设计。
