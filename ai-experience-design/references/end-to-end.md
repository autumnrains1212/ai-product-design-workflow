# 从规格到可运行交付

先核对需求基线、已有实现和本轮交付范围，再选择最小可验证路径。只做需求或设计时不扩展为生产开发；要求可运行项目时，不能以文档或画板存在代替实际运行。

## 实现前对齐

- 将功能、数据、接口、模型与工具规则映射到验收条件；复用项目既有技术与适用资产。
- 区分真实服务、规则模拟和固定样例。缺少模型、接口或凭据时，继续完成可执行部分、接口契约和接入步骤，并标明能力缺口。
- 按需求决定是否需要界面、服务端、持久化、异步任务或外部部署，不为简单问答和普通功能附加无关架构。
- 将权限、上下文、提示配置、输出解析与执行规则落实到代码或配置；详细规格见[AI 产品规格](ai-product-spec.md)和[PRD 模板](../assets/ai-native-prd-template.md)。

## 按能力落实关键规则

| 适用能力 | 实现与核验重点 |
|---|---|
| 普通确定性功能 | 输入校验、权限、业务规则、错误反馈及实际结果 |
| 问答、检索与提取 | 资料适用范围、检索过滤、来源关联、信息不足和可解析输出；外部资料作为数据处理，不获得执行授权 |
| 内容或多模态生成 | 请求约束、输出完整性、可审阅性、用户纠错；流式片段不得提前作为完整、有效结果执行 |
| 外部工具与业务写入 | 在可信边界检查权限、对象和参数；需要确认时绑定具体动作与资源，以真实回执或读回结果判断执行状态 |
| 异步业务操作 | 持有实际服务定义的操作身份，分开业务状态与查询结果；迟到响应不得覆盖较新结果或强行改变用户当前页面 |
| 可编辑持久化内容 | 区分草稿、已保存内容与正在提交的修改；需要时处理刷新恢复、取消、并发冲突和重复保存 |

没有对应能力的项目跳过该行，并在需求或交付记录说明不适用；不强制创建任务标识或保存状态。

## 重试、并发与数据保护

先判断操作是否产生副作用，再决定去重与重试策略。对于可重试的创建、支付、发送或其他写入，按服务能力使用稳定请求标识、服务端约束和可查回执；同一标识与不同参数发生冲突时明确拒绝或处理，不静默复用。

只读查询重试不创建新的业务操作。业务重新执行是独立动作，需要明确是否保留原结果、产生新记录或增加成本。超时只能表示未获得确定结果；先查询真实状态或回执，不能因响应丢失就直接宣称失败并再次写入。

涉及编辑与保存时，依据实际并发风险设计版本检查、字段差异和冲突选择，避免静默覆盖。保存成功但响应丢失后，应能确认原提交结果而非重复累积副作用。保存期间允许离开、取消或继续编辑时，要明确其真实语义，不能一边承诺放弃一边仍提交并强行导航。

按实际需要保留恢复入口和必要数据；失败不能无声丢弃用户输入。敏感资料、凭据和日志遵守需求中的访问与保留边界，不把密钥写入客户端或交付材料。

## 验证与定向修复

从 PRD 的验收条件选择当前改动所需检查。功能测试验证可观察结果；模型质量另用[输出质量方法](output-quality.md)评估。外部执行、数据写入和高影响机制需要覆盖适用的权限、重复提交、回执不确定、部分成功、故障恢复与并发场景。

在真实运行环境走通输入到可用结果，并检查相关失败分支。界面先读当前状态再操作；修改后重新加载并复测受影响路径。服务逻辑不能只靠界面截图证明，原生设计也不能靠代码存在证明。

模拟错误、测试桩和评审开关应与终端用户操作区分。记录哪些机制实际运行、哪些只做模拟，避免把注入故障当成第三方真实故障。低影响可逆修改按实际需要检查，不制造与风险无关的测试数量。

## 交付与恢复条件

提供实际源码与配置、设计位置、启动或查看方法、必要接口约定、已执行检查、已知限制及继续工作的条件。涉及模型时列出实际使用的版本与配置；未连接时提供接入约定和待执行评测，不报告虚构模型结果。

部署、发送、付费或其他外部操作按用户授权和实际环境执行。未部署的产物写明可运行或待部署；缺少联合评审、真实用户或生产数据时，分别保留待办，不因此抹去已完成的本地成果，也不将准备工作宣布为真实效果。
